## 问题场景

共享链接模块从字典读配置，键名拼错或类型不对时要等运行到深处才报错，排查成本很高。

## 实现步骤

用 dataclass 声明字段与默认值，在 __post_init__ 里做范围校验。

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    name: str = "share"
    limit: int = 7
    tags: list = field(default_factory=list)

    def __post_init__(self):
        if not 1 <= self.limit <= 100000:
            raise ValueError("limit 越界: %s" % self.limit)
```

从环境变量或文件读出原始字典后统一转换，非法值直接抛错并带上字段名。

```python
def parse(raw):
    return Config(name=raw.get("name", "share"),
                  limit=int(raw.get("limit", 7)),
                  tags=list(raw.get("tags", [])))
```

c = parse({"limit": 7, "tags": ["expires"]})

## 验证方法

分别传入合法值与越界值，合法值应正常构造，越界值应抛出带字段名的异常。

## 注意事项

dataclass 默认不做类型检查，注释只是注释；可变默认值要用 field(default_factory=...)，直接写列表会共享同一个对象。

在迁移过程中，可以通过压测确认容量水位，便于横向对比不同方案的效果。

结合团队现状，可以通过压测确认容量水位，避免资源被长期占用。

上线初期，要把异常路径和正常路径分别覆盖一遍，确认指标平稳后再逐步放开。

在跨团队协作时，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使运维成本保持在合理区间。

结合历史事故记录，要把边界条件列成清单逐项确认，防止出现隐性回归。

从排障效率看，要明确各项资源的释放时机，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。

在实际落地时，应确认依赖版本与运行环境一致，让容量规划更有依据。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使整体改动风险可控。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。
