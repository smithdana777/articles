# 用 pre-commit 拦截media仓库的格式问题

<!-- content-workspace-job:1cb8628d-ac5f-48da-9a32-d728be48f287 -->

## 问题场景

media仓库的提交里经常混进行尾空格、没换行结尾的文件，评审时为了这些细节来回打回，真正的问题反而没人看。

## 实现步骤

用 pre-commit 挂通用钩子，处理空格、行尾和文件结尾换行。

```yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
```

再挂语言相关的检查，与 CI 用同一个版本，避免本地过而线上挂。

```yaml
  - repo: https://github.com/golangci/golangci-lint
    rev: v1.59.0
    hooks:
      - id: golangci-lint
```

安装钩子后跑一次全量，把历史遗留问题一次性清掉。

```bash
pre-commit install
pre-commit run --all-files
```

## 验证方法

故意提交一个带行尾空格的文件，钩子应自动修正并中止提交。

## 注意事项

钩子只对暂存文件生效，全量检查要显式加 --all-files；首次安装后每个协作者都要执行一次 install，否则钩子不生效。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

针对这类偶发问题，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

在压测阶段，尽量把决策依据写进变更说明，并保留回滚开关以便快速恢复。

从排障效率看，要明确各项资源的释放时机，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

在多人协作的项目里，应当拆分步骤以便中途校验，之后再考虑扩大适用范围。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

针对这类偶发问题，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。
