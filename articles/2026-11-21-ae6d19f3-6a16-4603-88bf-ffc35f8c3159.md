# 用分区表归档用户表的历史数据

<!-- content-workspace-job:ae6d19f3-6a16-4603-88bf-ffc35f8c3159 -->

## 问题场景

用户表积累了几亿行历史数据，DELETE 老数据要跑几个小时，还产生大量 WAL，删完之后磁盘空间也不释放。

## 实现步骤

按时间范围建分区，每个分区对应一个时间段。

```sql
CREATE TABLE users_202611 PARTITION OF users
FOR VALUES FROM ('2026-11-01') TO ('2026-12-01');
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
```

归档时把整个分区从主表摘下来，元数据操作，瞬间完成。

```sql
ALTER TABLE users DETACH PARTITION users_202601;
```

查分区列表确认挂载关系，摘除后主表查询自动跳过该段。

```sql
SELECT inhrelid::regclass
FROM pg_inherits WHERE inhparent = 'users'::regclass;
```

## 注意事项

分区键必须出现在查询条件里才能裁剪，否则照样扫全部分区；主表上的唯一索引必须包含分区键，这是常见的建表失败原因。
