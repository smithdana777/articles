# 分片配置用 dataclass 做入参校验

## 问题场景

分片模块从字典读配置，键名拼错或类型不对时要等运行到深处才报错，排查成本很高。

## 实现步骤

用 dataclass 声明字段与默认值，在 __post_init__ 里做范围校验。

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    name: str = "shard"
    limit: int = 900000
    tags: list = field(default_factory=list)

    def __post_init__(self):
        if not 1 <= self.limit <= 100000:
            raise ValueError("limit 越界: %s" % self.limit)
```

从环境变量或文件读出原始字典后统一转换，非法值直接抛错并带上字段名。

```python
def parse(raw):
    return Config(name=raw.get("name", "shard"),
                  limit=int(raw.get("limit", 900000)),
                  tags=list(raw.get("tags", [])))
```

下游代码只接收已校验的对象，不再重复判断 None 或类型。

```python
c = parse({"limit": 900000, "tags": ["rows"]})

    parse({"limit": 0})

```

## 验证方法

分别传入合法值与越界值，合法值应正常构造，越界值应抛出带字段名的异常。

## 注意事项

dataclass 默认不做类型检查，注释只是注释；可变默认值要用 field(default_factory=...)，直接写列表会共享同一个对象。

对于刚接手的同学，要明确各项资源的释放时机，减少不必要的返工成本。

在多人协作的项目里，应当限定作用范围避免影响其他业务，同时把结论沉淀进团队文档。

在实际落地时，建议先在小流量环境验证行为是否符合预期，确认指标平稳后再逐步放开。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

在多人协作的项目里，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。
