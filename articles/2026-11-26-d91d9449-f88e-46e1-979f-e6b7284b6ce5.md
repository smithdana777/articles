# 司机推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:d91d9449-f88e-46e1-979f-e6b7284b6ce5 -->

## 问题场景

司机状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/driver/stream', (msg) => {
  state.count += 1;
  document.querySelector('#driver-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，确保线上行为始终可控。

如果数据量继续增长，需要评估对现有调用方的影响面，以便快速定位瓶颈。

在迁移过程中，可以通过日志补充上下文信息，使运维成本保持在合理区间。

从长期维护角度看，先把最小可复现的用例固定下来，以便后续复盘有据可查。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。

在资源受限的环境下，要避免在高峰期执行这类操作，避免问题积累到难以收场。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。

上线初期，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

对于刚接手的同学，应定期回顾相关监控指标，让排查路径更短。

在压测阶段，尽量把决策依据写进变更说明，之后再考虑扩大适用范围。

如果数据量继续增长，优先用工具把现状量化出来再动手，降低同类问题再次发生的概率。
