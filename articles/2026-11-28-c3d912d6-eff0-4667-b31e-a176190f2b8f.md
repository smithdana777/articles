# 任务页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:c3d912d6-eff0-4667-b31e-a176190f2b8f -->

## 问题场景

任务弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

关闭时先恢复焦点，再移除弹层节点，顺序颠倒会丢失目标。

```javascript
const dlg = document.querySelector('#task-dialog');
openDialog(dlg);
closeDialog(dlg);
console.log('focus restored', document.activeElement.tagName, 3);
```

## 验证方法

用键盘打开再关闭弹层，焦点应回到触发按钮，连续按 Tab 不应跳出弹层。

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

从长期维护角度看，先把最小可复现的用例固定下来，让容量规划更有依据。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。

上线初期，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

在资源受限的环境下，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

在跨团队协作时，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

在迁移过程中，可以通过压测确认容量水位，便于横向对比不同方案的效果。
