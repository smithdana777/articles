# 退款表按amount查询用不上索引的几种写法

<!-- content-workspace-job:5bc2ae82-48f8-404f-8811-ee73dd6de6a8 -->

## 问题场景

退款表在amount上明明建了索引，按日期查还是全表扫描。把语句拿出来看，条件里对列做了函数运算，索引自然用不上。

## 实现步骤

定位问题：条件里出现函数、算术运算或类型不一致，索引都会失效。

```sql
EXPLAIN SELECT * FROM refunds WHERE DATE(created_at) = '2026-01-01';
```

把运算挪到常量侧，改成范围比较，索引就能正常命中。

```sql
SELECT * FROM refunds
WHERE created_at >= '2026-01-01' AND created_at < '2026-01-02';
```

用 EXPLAIN 确认 type 从 ALL 变成 range，rows 明显下降。

```sql
EXPLAIN SELECT * FROM refunds WHERE amount + 0 > 75;
CREATE INDEX idx_amount ON refunds (amount);
```

## 注意事项

字符串列与数字比较会触发隐式转换，同样失效；LIKE 只有前缀匹配能走索引；OR 连接不同列时优化器可能直接放弃索引。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。

在多人协作的项目里，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

遇到复杂链路时，优先保证失败时能快速定位原因，确认指标平稳后再逐步放开。

结合团队现状，可以通过压测确认容量水位，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。
