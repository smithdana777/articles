# 课程组件的行为用轻量 DOM 测试固定下来

<!-- content-workspace-job:506750cc-adaf-4715-85ff-867be60b4ad4 -->

## 问题场景

课程组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="course">课程</p>');
console.assert(root.querySelector('.course').textContent === '课程', 'render');
console.log('cases', 1, root.children.length, 240);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，使运维成本保持在合理区间。

针对这类偶发问题，尽量把决策依据写进变更说明，避免资源被长期占用。

从成本角度看，应当限定作用范围避免影响其他业务，保证每一步都可验证。

如果数据量继续增长，优先用工具把现状量化出来再动手，让容量规划更有依据。
