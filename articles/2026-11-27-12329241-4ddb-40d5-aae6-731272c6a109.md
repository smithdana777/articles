# 密钥动画改用合成层属性避免重排

## 问题场景

密钥抽屉用 left 做滑入动画，低端机上明显卡顿，滚动时更严重。

## 实现步骤

把位移改为 translate3d，动画结束位置由 transform 决定。

```css
.drawer {
  position: fixed;
  inset: 0 auto 0 0;
  width: 320px;
  transform: translate3d(-100%, 0, 0);
  transition: transform .25s ease-out;
  will-change: transform;
}
```

用 will-change 提前提示浏览器提升图层，动画结束后及时撤销。

```javascript
const drawer = document.querySelector('.drawer');
function toggle(open) { drawer.classList.toggle('open', open); }
drawer.addEventListener('transitionend', () => {
  drawer.style.willChange = 'auto';
```

## 注意事项

will-change 不宜长期常驻，会占用显存；大量元素同时提升图层反而更慢。

在迁移过程中，可以通过日志补充上下文信息，避免问题积累到难以收场。

从长期维护角度看，先把最小可复现的用例固定下来，降低同类问题再次发生的概率。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

从排障效率看，应定期回顾相关监控指标，让容量规划更有依据。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。
