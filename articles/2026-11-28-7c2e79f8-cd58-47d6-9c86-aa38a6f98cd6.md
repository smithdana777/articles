# 生产批次组件的行为用轻量 DOM 测试固定下来

<!-- content-workspace-job:7c2e79f8-cd58-47d6-9c86-aa38a6f98cd6 -->

## 问题场景

生产批次组件改一次样式就担心逻辑被带坏，手工点页面回归又太慢。

## 实现步骤

用 jsdom 造一个最小文档环境，把组件挂到容器上。

```javascript
import { JSDOM } from 'jsdom';
const dom = new JSDOM('<!doctype html><div id="root"></div>');
global.document = dom.window.document;
```

断言渲染出的文本、类名与事件后的状态变化，不断言具体标签结构。

```javascript
export function mount(html) {
  const root = document.querySelector('#root');
  root.innerHTML = html;
  return root;
}
```

每个用例结束后清空容器，避免上一个用例的节点影响选择器。

```javascript
const root = mount('<p class="batch">生产批次</p>');
console.assert(root.querySelector('.batch').textContent === '生产批次', 'render');
console.log('cases', 1, root.children.length, 600);
```

## 注意事项

jsdom 不执行真实布局，依赖尺寸的断言要改用桩值；异步渲染要用 await 或宏任务等待后再断言。

上线初期，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

从可观测性角度，应确认依赖版本与运行环境一致，让排查路径更短。

对于刚接手的同学，应定期回顾相关监控指标，让容量规划更有依据。

从长期维护角度看，先把最小可复现的用例固定下来，降低同类问题再次发生的概率。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

在压测阶段，应把关键参数集中到配置中心统一管理，保证每一步都可验证。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。
